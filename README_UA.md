# Сервер Дитсадок — лабораторна 4 — варіант 34

Flask + Python + MySQL. Тема повернута до дитсадка. У проєкті 11 сутностей із попередніх лабораторних, повний CRUD, DTO, контролери, сервіси, DAO, запити 1:M і M:M та колекція Postman.

## Запуск

1. Розпакуй весь архів у звичайну папку. Не запускай BAT усередині ZIP.
2. Переконайся, що встановлені Python 3.10+ і запущений MySQL Server. Якщо Workbench може підключитися до MySQL, сервер уже працює.
3. Двічі натисни `START_SERVER.bat`.
4. При першому запуску залежності встановляться автоматично; потрібен інтернет.
5. У консолі введи адресу MySQL, порт, користувача та пароль. Зазвичай можна натискати Enter для `127.0.0.1`, `3306`, `root`. Пароль не відображається під час введення — це нормально.
6. Програма запропонує знайдену базу: спочатку `kindergarten_lab3`, якщо її немає — `kindergarten_db`. Enter підтверджує запропоновану назву. Вибери саме свою базу дитсадка.
7. Відкриється браузер із перевіркою підключення. Очікується `{"status":"ok","database":"connected"}`.

Залиш консоль відкритою. Зупинка: Ctrl+C. Наступного разу просто запускай той самий BAT — дані підключення зберігаються локально у `.env`. Щоб змінити їх, видали `.env` або запусти `START_SERVER.bat --configure` з командного рядка.

Основний порт — **5001**, щоб не заважати серверу JustMusic на 5000. Якщо він зайнятий, обирається наступний вільний. Фактична адреса друкується в консолі, а Postman-середовище оновлюється автоматично.

## Що змінюється в MySQL

Сервер використовує твою наявну базу дитсадка. Не потрібно перейменовувати чи переробляти музичну базу.

- Якщо база й усі таблиці з третьої лабораторної вже є — вони використовуються зі своїми даними.
- Якщо відсутні база або таблиці — створюються тільки відсутні.
- Якщо в ранній версії `addresses` немає поля `district`, додається `district VARCHAR(50) NULL`. Старі записи отримують NULL у новому полі.
- Відсутня `employee_groups` створюється як проміжна таблиця з ключем `(employee_id, group_id)`.
- Демонстраційні записи додаються тільки тоді, коли **всі 11 таблиць повністю порожні**. У частково заповнену базу автоматично нічого не дописується.
- Існуючі записи не перезаписуються. Запуск сервера не виконує DROP, TRUNCATE або DELETE.

Зміни застосовує `bootstrap.py`, вручну запускати SQL не потрібно. Для перегляду або ручного виконання є:

| Файл | Призначення |
|---|---|
| `sql/01_ensure_schema.sql` | Створити лише відсутні таблиці в `kindergarten_lab3` |
| `sql/02_seed_only_empty_database.sql` | Початкові дані; вручну запускати тільки на цілком порожній схемі |
| `sql/03_add_district_if_missing.sql` | Додати поле district, лише якщо воно відсутнє |

Якщо вручну працюєш із `kindergarten_db`, заміни назву в USE відповідного SQL-файлу. BAT сам підставляє обрану базу.

У `tests/lab3_fixture.sql` лежить окремий сценарій для автоматичних тестів. Не запускай його у своїй робочій базі: тести самі підставляють назву унікальної тимчасової схеми.

## Перша перевірка

У браузері відкрий адреси, використовуючи порт із консолі:

```text
http://127.0.0.1:5001/api/health
http://127.0.0.1:5001/api/employees
http://127.0.0.1:5001/api/children
http://127.0.0.1:5001/api/kindergartens/1/child_groups
http://127.0.0.1:5001/api/employees/1/groups
http://127.0.0.1:5001/api/relations/employees_groups
```

Перший перевіряє підключення, наступні читають таблиці, групи дитсадка (1:M) та групи працівника (M:M через employee_groups).

## Postman

У Postman імпортуй обидва файли з папки `postman`:

1. `Kindergarten_Lab4.postman_collection.json` — 79 запитів з перевірками.
2. `Local.postman_environment.json` — локальна адреса сервера.

У списку середовищ Postman вибери **Дитсадок локально**, тоді натисни Run collection і запусти всі папки по черзі, одну ітерацію.

Колекція створює власні тестові записи, запам’ятовує фактично отримані ID, перевіряє всі CRUD-операції та зв’язки, а наприкінці видаляє саме створені записи. Спеціально перевіряються також коди 400, 404 і 409; для відповідних запитів це очікуваний результат. Якщо перервати прогін, додані ним записи можуть залишитися в базі.

Відповіді списків мають формат `{"data":[...],"count":10}`. Одиночний запис — `{"data":{...}}`. Цей формат відрізняється від колишнього музичного сервера, тому використовуй нову колекцію.

## Де що знаходиться

| Файл або папка | Що робить |
|---|---|
| `START_SERVER.bat` | Готує Python-середовище, встановлює залежності та запускає сервер |
| `bootstrap.py` | Налаштування підключення, сумісність схеми, перший запуск |
| `main.py` | Звичайний запуск Flask без підготовки схеми |
| `app/controller/api.py` | HTTP-запити CRUD і зв’язків |
| `app/service/` | Перевірки даних та послідовність операцій |
| `app/dao/` | SQL-запити з параметрами |
| `app/dto/record_dto.py` | Формує JSON-сумісні DTO |
| `app/domain/schema.py` | Опис 11 таблиць, ключів і полів |
| `API_REFERENCE.md` | Приклади запитів, пояснення команд і список скрінів |

У звичайному запуску через `main.py` або `run.py` використовується `.env`, який створив BAT. Основний спосіб запуску — `START_SERVER.bat`.

## Помилки запуску

- **Python not found:** встанови Python 3.10+ з python.org, увімкни додавання до PATH, запусти BAT знову.
- **Access denied / неправильний пароль:** повторно введи дані з підключення Workbench.
- **MySQL недоступний:** відкрий підключення Workbench або запусти службу MySQL; перевір порт.
- **Немає прав створювати таблиці:** підключись користувачем, який створював твою навчальну базу.
- **Не вдалося встановити залежності:** перевір інтернет і повтори запуск.
- **Закрив консоль — адреси не відкриваються:** знову запусти BAT, сервер має працювати під час перевірки Postman.
